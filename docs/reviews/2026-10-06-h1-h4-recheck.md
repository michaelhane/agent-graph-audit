## H1: partly fixed

| Fixture | Score |
|---|---|
| Plain repo, one-line `CLAUDE.md` (baseline) | 8% |
| Full copy at `.claude/skills/agent-graph-audit/` | 8% ✅ fixed |
| Same, at `.claude/plugins/x/skills/agent-graph-audit/` | 8% ✅ fixed |
| Same, but frontmatter is `name: "agent-graph-audit"` (quoted, valid YAML) | **69%** (raw 86) |
| Same, but renamed to `name: agent-graph-audit-v2` | **69%** (raw 86) |

- **Cause:** detection relies only on the regex `^name:\s*agent-graph-audit\s*$`. It doesn't allow quotes or renamed copies, and it can match anywhere in the first 4,000 characters, not only in the frontmatter.
- **Fix:**
  - Allow quotes: `^name:\s*["']?agent-graph-audit["']?\s*$`, applied to the frontmatter block only.
  - Also recognise the skill by its folder layout: any folder containing both `scripts/score_setup.py` and `references/rubric.md`. This catches renamed copies.
- **Side effects of the new skip** ✅:
  - Scoring the skill's own folder now returns **0%, files_scanned 0**, with no explanation.
  - Any folder with a `SKILL.md` named `agent-graph-audit` is hidden entirely. A repo with one at its root scores 0%, including a `.env` with a live key. This only ever lowers a score, so the gaming risk is low, but the result is silent.
  - **Fix:** add a report line such as `Skipped (this skill): .claude/skills/agent-graph-audit`.

## H4: misses fixed, but 9 new false positives ✅

The 5 missed formats and the placeholder case from the first review now all give the right result. But these safe lines are now **flagged as inline secrets**; the old pattern flagged none of the first five:

| Line | Why it's safe | New result |
|---|---|---|
| `const apiKey = process.env.OPENAI_API_KEY;` | Reads from the environment, which is correct practice | FLAGGED |
| `api_key = os.environ.get("OPENAI_API_KEY")` | Same | FLAGGED |
| `secret_key = settings.SECRET_KEY` | Settings lookup | FLAGGED |
| `tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")` | Not a secret (`token` + `izer`) | FLAGGED |
| `token_path = "/var/run/secrets/kubernetes.io/serviceaccount/token"` | A file path | FLAGGED |
| `    access_token: AccessTokenResponse` | A type annotation | FLAGGED |
| `API_KEY=your_api_key_here` in `.env.example` | Placeholder with underscores | FLAGGED |
| `API_KEY="YOUR_API_KEY_HERE"` in `.env.example` | Placeholder in capitals | FLAGGED |
| `OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxx` in `.env.example` | Placeholder | FLAGGED |
| `token: ${{ secrets.GITHUB_TOKEN }}` (control) | Secret reference | pass ✅ |
| `API_KEY = "sk-proj-abc…"` in `config.py` (control) | Real literal | FLAGGED ✅ |

- **Impact:** the check loses 10 harness points, and the citation points the user at their *safe* code as the secret.
- **Causes:**
  1. Quotes are now optional everywhere, so any expression of 12 or more characters on the right-hand side counts as a value.
  2. Adding `.` and `/` to the value pattern lets it match attribute lookups (`process.env.X`) and file paths.
  3. Allowing extra word characters around the keyword also catches `tokenizer`.
  4. `PLACEHOLDER_RE` only recognises a hyphenated `your-` at the start of the value.
- **Fix:**
  - **Code files:** require a quoted literal.
  - **`.env*` files:** allow unquoted values, since every value there is a literal.
  - **Values to skip:** anything that starts with `/` or `$`.
  - **Keyword followed by a letter:** add `(?![a-z])` after the keyword. `SECRET_KEY` still matches, `tokenizer` doesn't.
  - **Placeholders:** widen to `your[_-]`, `_here$`, `replace`, `changeme`, `placeholder`, `dummy` and `x{6,}`, searched anywhere in the value.
  - **⚠ Don't add `example` to that anywhere-search.** The `aws slash` eval fixture uses AWS's documented example key, `…CYEXAMPLEKEY`, and must still be flagged. Keep `example` as a prefix-only rule, or change the fixture value.
- **Minor:** the `<` alternative in `PLACEHOLDER_RE` can never match, because `<` isn't allowed in the captured value.

## New issues

### N1. About 4.8× slower on big repos ✅

| Repo: one `CLAUDE.md` plus 50,000 files in `node_modules/` | Best of 3 |
|---|---|
| Original | 0.59 s |
| Patched | **2.81 s** |

- **Causes:**
  - `own_skill_dirs` runs a second full `rglob("SKILL.md")` over the whole tree without applying the skip-list.
  - `iter_files` now calls `path.resolve()` on every file.
  - The original also walked all of `node_modules` and only filtered afterwards, so both versions do that.
- **Fix:**
  - Use a single `os.walk`, removing skip-list names from `dirnames` in place so those folders are never entered.
  - Detect the skill's `SKILL.md` during that same walk.
  - Resolve only `root`, and compare against the unresolved paths. Paths from walking `root` are already under `root`.

### N2. A symlinked instruction file pointing outside the repo is now dropped ✅

`CLAUDE.md` → `../shared/CLAUDE.md`:

| Version | Instruction file check |
|---|---|
| Original | passes (`CLAUDE.md:1`) |
| Patched | fails; file not read |

- **Cause:** `path.resolve().relative_to(root)` raises `ValueError`, and the file is skipped. If that was intended as a safety boundary, document it. If not, the N1 fix (unresolved relative paths) removes it too.

### N3. Docs out of date 📖

- `README.md` isn't in the zip. If it's unchanged, it still says "27 cases" (now 35) and "This folder scores itself 69%" (now 0%, because of the H1 skip).
- `SKILL.md` now points to `harness-creator`. That skill isn't among the skills available in this session, so I can't confirm it exists where this one gets installed.
- `names_blob()` now has no callers at all, and `file_text()` is still unused.
